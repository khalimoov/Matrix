# Matrix VMS

Собственная система управления видеонаблюдением (VMS): аналог по функциям систем вроде Dahua DSS, Hikvision iVMS или Milestone, написанный с нуля.
Работает с любыми IP-камерами и регистраторами через открытые стандарты **RTSP** и **ONVIF**, поэтому лицензии производителей не нужны.

> Код написан независимо, ни строки не взято из чужих продуктов. Название, логотип и интерфейс свои.
> Не используйте в продукте чужие товарные знаки (например, «DSS» или «Dahua»): это нарушение прав на товарный знак.

## Возможности (версия 0.1)

| Модуль | Что умеет |
|---|---|
| **Устройства** | Добавление камер Dahua, Hikvision, ONVIF или по RTSP-адресу. Каналы регистраторов. Группы. Поиск камер в сети (WS-Discovery) и автонастройка потоков через ONVIF |
| **Живой просмотр** | Видеостена 1/4/9/16/25 окон, перетаскивание камер, разворот окна, полноэкранный режим, переключение «субпоток / основной поток (HD)». WebRTC с задержкой меньше секунды, запасной вариант HLS |
| **PTZ** | Управление поворотом и зумом (ONVIF), пресеты |
| **Запись и архив** | Непрерывная запись, срок хранения для каждой камеры, шкала времени за сутки, скорость 0.5×–8×, выгрузка фрагмента в MP4 |
| **События** | Журнал: камера в сети / потеря сигнала, входы, неудачные попытки входа, изменения настроек. Обновляется в реальном времени |
| **Пользователи** | Роли: администратор, оператор (просмотр, архив, PTZ, события), наблюдатель (только живой просмотр). Защита от перебора паролей |
| **Состояние системы** | Камеры в сети, доступность медиасервера, свободное место на диске |

## Архитектура

```
 Браузер ──HTTP/WebRTC──► Matrix (Go) ──API──► MediaMTX ◄──RTSP── камеры / регистраторы
                            │  SQLite                │
                            │  пользователи, камеры,  └─► запись на диск (fMP4)
                            │  события
                            └─ ONVIF: поиск, профили, PTZ ──► камеры
```

- **server/**: сервер на Go. API, вход и права, настройки камер, ONVIF, журнал событий, контроль состояния. Хранит данные в SQLite.
- **web/**: веб-клиент на React и TypeScript.
- **[MediaMTX](https://github.com/bluenviron/mediamtx)**: медиадвижок с открытой лицензией MIT. Забирает RTSP-потоки, пишет архив, раздаёт видео по WebRTC/HLS. Matrix управляет им через API. Сам MediaMTX наружу не открыт: видео доступно только через Matrix после входа.

## Быстрый старт (Docker)

Нужен Linux-сервер с Docker в одной сети с камерами.

```bash
git clone <этот репозиторий> matrix && cd matrix
docker compose up -d --build
docker compose logs matrix | grep password   # пароль пользователя admin
```

Откройте `http://<IP-сервера>:8080`, войдите как `admin` и сразу смените пароль (кнопка «Пароль» вверху).

В брандмауэре откройте порты **TCP 8080** (веб-интерфейс) и **UDP + TCP 8189** (видео WebRTC).
Если клиенты подключаются из-за NAT или через интернет, укажите внешний IP в `MTX_WEBRTCADDITIONALHOSTS` в `docker-compose.yml`.

### Добавление камеры Dahua

1. «Устройства» → «Добавить камеру» → тип **Dahua**.
2. IP-адрес, логин и пароль камеры. Для регистратора укажите номер канала.
3. Для PTZ включите ONVIF в веб-интерфейсе камеры, укажите адрес `http://<IP>/onvif/device_service` и нажмите «Проверить».

Советы:
- Для субпотока лучше выбрать кодек **H.264**: браузеры не всегда показывают H.265 по WebRTC. Для H.265 Matrix автоматически переключится на HLS.
- Субпоток используется в сетке, основной поток (кнопка HD в окне) — при развороте и для записи.

### Сколько места нужно под архив

Примерно `битрейт (Мбит/с) × 10,8 ГБ` в сутки на камеру. Камера 4 Мбит/с — около 43 ГБ в сутки, за 7 дней около 300 ГБ.
Чтобы хранить видео на отдельном диске, замените том `recordings` в `docker-compose.yml` на папку этого диска.

## Разработка

Нужны Go 1.24+, Node.js 22+ и [MediaMTX](https://github.com/bluenviron/mediamtx/releases).

```bash
# 1. Медиасервер
mediamtx deploy/mediamtx.yml

# 2. Сервер Matrix (http://localhost:8080)
cd server && MATRIX_ADMIN_PASSWORD=admin12345 go run ./cmd/matrix

# 3. Веб-клиент с горячей перезагрузкой (http://localhost:5173)
cd web && npm install && npm run dev
```

Проверки: `cd server && go vet ./... && go test ./...`, `cd web && npm run build`.

### Настройки сервера (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MATRIX_ADDR` | `:8080` | адрес веб-сервера |
| `MATRIX_DATA_DIR` | `./data` | папка базы данных |
| `MATRIX_WEB_DIR` | `./web` | папка собранного веб-клиента |
| `MATRIX_RECORDINGS_DIR` | `./recordings` | папка архива (для статистики диска) |
| `MATRIX_ADMIN_PASSWORD` | случайный | пароль `admin` при первом запуске |
| `MATRIX_SESSION_TTL` | `12h` | время жизни сессии |
| `MATRIX_SECURE_COOKIES` | `false` | `true`, если Matrix работает за HTTPS |
| `MATRIX_MEDIAMTX_API` и др. | `http://127.0.0.1:…` | адреса MediaMTX |
| `MATRIX_DEBUG` | `false` | подробный лог |

## План развития

- **Этап 2:** детекция движения и тревожные входы камер (ONVIF Events), запись по событиям и расписанию, уведомления (Telegram, e-mail).
- **Этап 3:** права на отдельные камеры и группы, электронная карта объекта, туры (автопереключение раскладок), несколько мониторов.
- **Этап 4:** ИИ-аналитика (люди, транспорт, номера), поиск по архиву, приложение для телефона.
- **Этап 5:** несколько серверов записи под одним центром, резервирование, HTTPS из коробки, многоязычный интерфейс.

## Безопасность

- Пароли пользователей хранятся как bcrypt-хеши, сессии — как SHA-256-хеши токенов.
- Пароли камер хранятся в базе открытым текстом (они нужны для подключения к камере), поэтому ограничьте доступ к тому `data`.
- В продакшене ставьте Matrix за HTTPS (например, Caddy или nginx) и включайте `MATRIX_SECURE_COOKIES=true`.
